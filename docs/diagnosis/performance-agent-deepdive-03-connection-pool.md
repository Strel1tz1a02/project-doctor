# 问题三 深度解析：连接池耗尽 / 泄漏

> 本文回答三件事：①连接池耗尽的**底层原因**；②如何通过**相关指标**诊断；③**为什么**这些指标能诊断（因果链）。

---

## 一、问题的本质

数据库连接是**稀缺资源**（池有固定上限），当连接被用完或占满后，新请求拿不到连接，只能**排队等待甚至超时失败**。

---

## 二、底层原因

### 2.1 根本机制：连接池是"租借—归还"模型

- 连接本身昂贵（TCP 握手 + DB 会话状态），所以用**连接池**复用固定数量的连接。
- 池的模型是"**借出 → 使用 → 归还**"；池的健康取决于两件事：**归还是否发生**（有没有泄漏）、**周转是否够快**（每条连接被占多久）。

### 2.2 三种具体根因

| # | 根因 | 说明 | 特征 |
|---|---|---|---|
| 1 | 连接泄漏 | 借出后没在 `finally` 里归还，用一次丢一个 | 空闲连接随时间单调递减，最终耗尽 |
| 2 | 池太小 | 并发需求长期超过池上限 | 活跃连接长期等于上限，且有排队 |
| 3 | 慢查询占满 | 连接都被长时间占用的慢 SQL 拿着，周转慢 | 少数 SQL 占用连接时间极长 |

> 关键点：三种根因的**表象都是"拿不到连接"**，但修法完全不同（修泄漏 / 调大池 / 压慢查询）。所以 Agent 必须先分类根因，再给方案——这正是"根因分类"模块存在的意义。
>
> 更深一层：其中"慢查询占满"的根因在问题一（慢查询），**连接池耗尽只是症状**。诊断要沿因果链回溯到根因，而非止步于症状（否则会盲目调大池掩盖问题）。

---

## 三、如何通过相关指标诊断

### 3.1 诊断指标清单

| 指标来源 | 指标 | 诊断信号 |
|---|---|---|
| **连接池指标** | 活跃连接数 / 空闲连接数 | 活跃打满、空闲趋零 |
| | 获取连接等待时间 | 上升 = 供不应求 |
| | 等待队列长度 | 积压 |
| **日志** | `timeout waiting for connection` | 拿不到连接的显式错误 |
| **数据库指标** | DB 连接数 | 达到上限 |
| **应用指标** | 超时错误率、p99 | 飙升 |

### 3.2 诊断流程（关键在分类根因）

```
① 现象：大量 timeout 日志 + 获取连接等待时间飙升
        ↓
② 看池指标：空闲连接是否随时间递减？
   递减 → 泄漏（借了不还）
   不递减但活跃=上限且有排队 → 池太小
   连接被少数 SQL 长时间占用 → 慢查询占满
        ↓
③ 对症：修泄漏 / 调大池 / 压慢查询
```

### 3.3 具体例子

`pool_size=10`，某接口的查询因缺索引变慢（8s/条），并发下 10 条连接全部被慢查询占住。新请求获取连接等待时间从 1ms 涨到 5s，大量 `timeout waiting for connection`。

诊断：活跃连接数=10 打满，但空闲连接不递减（排除泄漏）；连接占用者都是同一批慢 SQL → 根因是"慢查询占满"。修复：回到问题一压慢查询，而非盲目调大池。

---

## 四、为什么这些指标能诊断出该问题（因果链）

### 4.1 为什么"空闲连接随时间递减"能定位泄漏

泄漏 = 借出后不归还。池里的连接只会"有去无回"，表现为**空闲连接数单调下降、活跃连接数单调上升，且与并发量无关**。这条"只减不增"的曲线，是泄漏区别于"池小/慢查询"的决定性证据——后两者的空闲连接会随请求结束而回升。

### 4.2 为什么"获取连接等待时间"能暴露供不应求

连接池的等待时间 = 请求排队等空闲连接的时间，是"供给不足"的**直接度量**。池耗尽（无论哪种根因）必然导致等待时间上升，所以它是"问题存在"的通用哨兵。

### 4.3 为什么 timeout 日志是明确信号

`timeout waiting for connection` 是连接池在"等不到空闲连接"时的**显式报错**，语义明确、无歧义——出现它，就等于连接池已经耗尽。这是低检测难度的原因。

### 4.4 为什么需要根因分类（而不能只看等待时间）

等待时间只能证明"供不应求"，不能证明"为什么"。泄漏/池小/慢查询对等待时间的影响是**不可区分的**（都让它上升），但对"空闲连接曲线"和"占用时长分布"的影响不同。所以必须用**多个信号的组合**才能分类——这就是它检测难度标"中"的原因。

## 五、对 Agent 模块的落点

```
M1 指标采集器（池活跃/空闲/等待时间）
  → M5 日志检索器（timeout 日志）
  → M9 根因分类器（泄漏 / 池小 / 慢查询占满）
  → M7 代码分析器（定位泄漏点：缺 finally 释放）
  → M10 优化模板库（修释放 / 调池 / 压慢查询模板）
  → M12 复测执行器（等待时间↓、timeout 消失）
```
