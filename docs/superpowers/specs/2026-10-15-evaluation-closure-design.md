# Project Doctor 端到端评估闭环设计

日期：2026-10-15。状态：待用户审阅。

## 目标与事实

目标是用仓库现有评测器证明真实 Agent 的诊断与修复闭环，并让全量评估通过。通过指 `datasets/evaluation/run_eval.py` 对当前全部用例输出 `global.overall_passed=true`、无缺失运行包、`false_verified_count=0`，且运行包来自真实执行。评测器 fixture、合同测试和合成探针通过，只证明各自的工程接口。

当前 `main` 为 `df95aaa5`，工作区干净。数据集有 45 例、9 类问题；平台声称支持慢查询、N+1、深分页，其他类型的期望结论是线索或未定论。最近可核对的六例真实慢查询诊断为 4/6、一次误验证：case-05 错误升级 `verified`；case-02 保留了 `lead` 和必要限制，但评分器的整段文本匹配及位置容差造成误判。该轮只评诊断，不证明独立修复。当前执行机无可用 `docker` 命令，也未设置 `PROJECT_DOCTOR_PLATFORM_DSN`；必须把真实运行与静态回归分开报告。

## 可选路径与选择

1. **只调提示词和报告措辞**：改动小，但不能补运行证据、修复交接和独立复测，难以稳定通过硬闸门。
2. **一次性扩展全部九类诊断**：覆盖广，但新增机制与现有评估失败混在一起，无法定位回归原因。
3. **按现有能力和失败类型逐段闭环**（采用）：先修真实误验证与错误评分，再完成三类受支持问题的运行和修复证据，最后对其余六类诚实地给出线索或未定论；每段都以完整运行包评分。

## 设计

### 1. 统一运行与证据边界

编排一次用例时，只把 `datasets/<case>/project/` 和用户可见症状交给 Agent。`case.json`、维护者 README、评测文档和答案不得进入模型会话或被 SUT 引用。平台创建、重置并恢复隔离环境；业务代码控制任务状态、预算、重试和工具权限。Agent 选择假设与允许的实验，不提交任意 SQL、路径或外部地址。

每次运行保存 `business-tool-calls.jsonl`、`session.jsonl`、`bundle.json`、`summary.json`、SQL/计划/锁证据、报告、恢复结果。导出器只从已保存事实生成运行包。运行包绑定 Agent commit/源码哈希、模型配置引用、数据集与评测器哈希、评估 ID、目标 commit 和原始目录。缺少关键字段时标记缺失，不补造默认成功值。

### 2. 候选、结论与修复决策

诊断采用“候选筛查 → 证据核对 → 有限对照”的顺序。慢 SQL、全表扫描或静态代码命中只是线索；`verified` 需要有效业务请求、SQL 与代码关联、实际执行计划和统计、可比单变量实验、竞争解释处理及恢复证据。数据分布只覆盖一种参数时，结论限定在该参数与快照，不能推及其他参数；case-05 应因此停在 `lead`。测量未达区分阈值时保留 `lead`，不为提高召回而放宽阈值。

修复只读取本次持久化 Finding，由独立会话回答“是否该改、改哪里、改得怎样”。不该改时保留真实会话和停止理由；该改时记录补丁实际改动行、构建结果、独立复测的业务一致性和收益。诊断报告、修复登记文件和评估运行包互相校验身份；禁止预置金标准 Finding、预写补丁或凭一次更快请求报收益。

### 3. 评估与迭代

先冻结现有评测器和数据集哈希，复核每个失败的原始包。区分产品缺陷、评测器误判和环境不可用；case-02 的文本匹配与位置容差只能经评测方修正规则、重冻版本并保留旧分数，不能由 SUT 读取答案或针对性写文案。先跑少量正常、边界、失败及应修/克制/越界用例，再无 `--only-bundled` 运行全部 45 例。缺失用例、任一次误验证、任一用例硬闸门失败，都判整轮未通过。

优先级：① case-05 误验证；② case-02 评分误判；③ 三类受支持问题的真实诊断、修复和复测证据；④ 其他六类的诚实停止与全量运行包。每一阶段记录用例通过数、误验证数、漏判数、失败闸门和可追溯运行包；分数只与相同版本和范围的结果比较。

## 异常与停止条件

- Docker、平台 MySQL、AGH 或目标项目启动条件缺失：只运行可用的静态/合同检查，记录真实验收阻断，不声明评估通过。
- 业务断言失败、锁覆盖未知、参数/快照不可比、证据损坏、恢复失败：输出 `lead` 或 `unclassified`，保存失败轨迹；不得输出 `verified`。
- 修复任务与 Finding/提交不一致、修复会话缺失、构建失败或复测不可归因：拒绝修复成功结论。
- 评测器变化：另记版本、哈希与评估 ID，旧报告原样保留；不把不同口径的分数直接比较。

## 验收

1. `scripts/check.ps1`、数据集三守卫、评测器单测和 14 例金标准回归通过；这些是工程门槛。
2. 至少有真实正常、边界、失败、应修、克制、越界六种路径，各自具备完整原始包、身份链和恢复证据。
3. 全量 45 例均有真实运行包，评测器不使用 `--only-bundled`，`overall_passed=true`、`cases_missing_bundle=[]`、`false_verified_count=0`；报告可追溯至原始包与冻结版本。
4. 若外部运行前提缺失，交付完成的代码、测试与未通过/未运行清单；不得用 fixture 分数替代第 3 条。
