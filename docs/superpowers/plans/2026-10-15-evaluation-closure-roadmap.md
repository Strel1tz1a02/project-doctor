## 交接原则

- 按顺序执行。每阶段先核验 HEAD、现有实现和环境；代码已存在就复用，只有真实失败才改。
- 实现者逐任务采用 RED→GREEN→回归→可审查提交。每阶段输出：改动文件、测试结果、真实运行 ID、原始包路径、评分与未完成项。
- Docker、平台 MySQL 或 AGH 缺失时，完成可做的工程检查并明确阻断；不能宣称真实验收通过。
- 所有评分器/数据集更改要保存旧结果、独立说明理由、更换版本哈希和评估 ID。不能针对答案写 SUT 提示词或降低硬门槛。
- 用户要求子 Agent 先确认；此路线按单 Agent 顺序执行。
