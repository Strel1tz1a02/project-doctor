# 持续并发负载实施计划

目标：真实执行重启准备、并发预热和持续测量，保存可核验的请求记录。正式默认并发 4、预热 10 秒、测量 60 秒。
约束：不修改 datasets，不向模型提供答案；保持串行诊断现有门槛。

1. 增加 TimedLoadSpec、请求/窗口结果合同；ExperimentSpec/Result 兼容增加可选字段。
2. 实现固定工作者的持续 HTTP 请求、共用连接池、唯一请求标记、业务断言、预算上限、窗口完整性和 P95。
3. Docker 每组恢复基线、应用索引（候选组）、关闭数据库缓冲池自动加载后重启数据库及应用，记录前后容器启动时间和配置。
4. 接入既有 run_experiment 的预留、独占、结算和恢复链路；保存原始窗口制品。持续负载暂不具有完整逐 SQL/锁观测，因此输出 lead，不能以 HTTP 收益直接 verified。
5. 回归失败、超时、请求上限、取消、分组隔离与旧合同兼容；做一次真实目标的 4/10/60 对照。

验收重点：不能缩短 60 秒后标完成；预热不计入正式 P95；候选/基线预算独立；失败请求不能被成功样本隐藏；取消后不能留下请求工作者或跳过恢复。
后续完整诊断需要高吞吐的逐 SQL 与锁观测，再扩展证据门槛；不能直接复用串行样本数规则或放宽门槛。
