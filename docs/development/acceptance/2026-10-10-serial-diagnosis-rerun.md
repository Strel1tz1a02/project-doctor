# 恢复后六例串行诊断复跑

本轮只评诊断，不运行额外修正复测，不把修正收益或修正后业务正确性计入分数。
诊断中的索引对照用于验证机制；模型自主提出假设并从通用受控配方中选择一个实验。
目标代码、镜像、串行负载、预热、样本数与预算沿用上一轮；各例任务与 AGH 会话全新。
恢复后的 78 个平台源文件在模型运行前后均匹配上轮 SHA-256，过程中没有修改诊断逻辑。

| --- | --- | --- | --- |

诊断通过 3/6，误验证 1 次，整轮未通过。
根因召回均值和代码位置命中率均为 0.75；过程覆盖率 1.0，制品完整性通过。
诊断口径均分 0.5614；六例都超过至少一个现有成本预算项，成本作为原评估器的软约束计分。
串行、预热后的测量结果不代表持续并发或重启冷缓存条件。

## 运行与边界

六例业务任务均 completed，各完成一次索引实验和十个正式请求；业务工具错误为 0。
所有实际实验恢复通过，报告和制品 hash 通过，各例均无残留任务容器。
第四例业务已经发布报告，但 AGH 会话以 blocked / exitCode=4 结束，保留在原事件与摘要中。
其余模型会话正常 completed。

第四例启动前测试脚本发现旧任务号使用 round2b 而非 round2，主动停止，未调用该例模型；
修正任务号替换后继续后三例，前三例不重跑、不覆盖。此修正只作用于 Git 忽略目录的测试脚本。

模型只接收公开 project 源码与既有诊断指令，不接收 case.json 或评分答案。
评分复用冻结评估器，按用户范围仅排除 recommendation_effective / correctness_preserved 的指标和门槛；
其他根因、位置、证据、过程、恢复、成本及误验证判据不变。
步骤参数合法性指标使用评估器的通用字段而非实际 MCP 合同，其 0 值不能解释为本轮参数全部非法；
该步骤指标不计总分。API 成本及 token 仍未可靠计量。

原始结果位于 `runtime-data/serial-evaluation-20261010-live/`：
各 `sut-NN/session.jsonl`、`business-tool-calls.jsonl`、`bundle.json` 与报告保存完整轨迹；
`diagnosis-score/report.json` / `report.md` 保存诊断评分；`evaluator-frozen.json` 保存评估器冻结记录。

## 清理与结论

AGH 官方守护进程已停止，私有 MCP 服务文件已恢复原配置。
本轮启动的平台数据库已停止，其他五个项目容器保持运行。
已恢复的是六例可执行的 SQL 诊断闭环；本轮成绩不证明所有诊断门槛已正确。
后续应分别处理真实测量波动、边界说明、倾斜数据的过度验证和反例评分合同，不能调低门槛追求分数。
