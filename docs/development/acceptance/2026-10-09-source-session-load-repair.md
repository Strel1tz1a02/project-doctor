# 源码身份、AGH 会话与负载声明修复

本轮修复测试可信性，不修改评估案例、标准答案、评分器或诊断收益门槛。

## 已修内容

### 1. 任务必须绑定实际源码

此前 Docker 复制 Settings.target_repo_root，但报告的提交号来自 ProjectInput。
路径或提交号不一致时可能出现“执行 A 项目，报告写 B 项目”的结果。

现在真实入口在创建任务、准备环境和 Docker 复制前分别校验：

- repo_path 是配置目标仓库的绝对路径。
- 该目录是自身 Git 仓库根目录。
- commit 是与 HEAD 相同的完整 40 位提交号。
- 没有已跟踪文件修改或未忽略的未跟踪文件。

错误输入在创建任务前被拒绝；准备前再次校验能捕获创建后发生的修改。
复制前校验失败不会删除已有隔离副本。旧合同仍可读取，local: 别名与短提交号不再能启动真实执行。
忽略文件仍按现有复制规则处理，制品记录实际源码 hash；本次没有新增原子源码快照或任意技术栈支持。

### 2. AGH 重试使用新会话

新增 scripts/run_agh_case.py，顺序使用官方 daemon stop/start/status，确认成功后才调用模型。
每次尝试新建 workspace 和 create_task 操作号。AGH CLI 的会话由 cwd 派生，因此不复用失败尝试的会话。
模型退出、启动失败或超时后仍尝试官方 stop；关闭失败会让启动器报错并在 lifecycle.json 标记失败。

前置条件：专用 AGH Home 已配置正确 MCP 目标与 manifest，一次只运行一例。
脚本不切换 MCP 注册；源码绑定只能防止目标目录不一致，不能代替场景 manifest 的配置核对。
日志包含逐阶段结果；密钥从外部环境继承并按 SECRET/API_KEY 环境变量值脱敏。
使用方法见 [AGH 接入说明](../../../agh/README.md)。

### 3. 拒绝伪并发结果

当前运行时是串行测量。过去仅在有 warmup 的新实验中拒绝并发，旧实验可以绕过。
现在所有实验都会拒绝 concurrency/arrival_rate 场景；诊断门槛也拒绝把这类历史结果升为 verified。
没有实现并发调度，也不会把并发场景偷偷转换成串行后按正式协议计分。
