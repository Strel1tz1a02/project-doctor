# 真实项目样例候选清单

本文件记录为 `datasets/` 补充「真实项目来源」样例时，按 9 类 `problem_kind` 逐类检索到的候选项目及其核验结果。撰写与筛选严格遵循《数据集结构规范》与本次任务约定，要点如下：

- **来源**：仅取自 GitHub 等公开真实项目，全部历史可追溯（仓库链接 + 固定 commit/tag + 许可证 + 关键文件路径）；不使用虚构项目、不可访问代码或无法确认来源的片段。
- **分类**：按既定 9 类问题逐类建立候选，每类下区分「原生问题项目（首选）」与「加工型项目（次选）」。
- **原生问题项目**：项目自身已通过 issue / PR / 安全公告 / README / TODO 等明确说明存在目标问题；须定位到对应代码位置（`path:line`）并引用原始说明作为证据。若问题已修复，则回退到「问题存在时」的 commit/tag。
- **加工型项目**：找不到合适原生问题项目时采用；须规模适中、依赖清晰、可构建/运行；只做最小必要加工，明确区分原始代码与人为改造，记录改动内容、动机与预期优化目标；不得伪装成原生问题项目。
- **证据口径**：仓库存在性、默认分支与分支 HEAD 用 `git ls-remote`（含 `--symref`）核验；issue/PR 状态与正文经 GitHub 公开 API 或公开页面核验。**逐条 commit SHA、issue/PR 编号、代码位置均可回溯，未做任何编造。**

> 说明：本清单为「候选阶段」产物。每条候选的**许可证**字段标注为「待核验」者，将在最终入选时逐库读取仓库根 `LICENSE` 文件确认，并写入用例 `provenance.license`；确认前不臆断许可类型。
>
> 候选的**固定版本**一栏，凡标注问题「已修复」者，给出问题存在时的历史 commit/tag；凡指向分支 HEAD 者，给出核验当日的 HEAD SHA，最终落盘须复取该 commit 以保证 `path:line` 稳定。
