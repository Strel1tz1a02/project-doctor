# 运行包采集模块交接说明

> 面向读者：负责**执行 / 采集**的组员（跑实验、跑被测 Agent 的人）与队长
> 关联文档：`docs/评测器能力边界说明.md`（先读它）
> 交付物：`evaluation/collect_run_bundle.py`（模块） + 本说明（协作边界）

---

## 1. 一句话

`collect_run_bundle.py` 是**执行侧与评测侧之间的「交接模具」**：
它把「原始代码 + 修改后代码」映射成评测器需要的**全部评分参数**，产出**运行包（run bundle）**。

> **它不跑实验。** 真正采集数据的动作由执行侧的「采集后端」完成；
> 本模块只负责**定义契约、组装运行包、做完整性与溯源校验**。

---

## 2. 位置与定位

| 项 | 内容 |
| --- | --- |
| 模块路径 | `datasets/evaluation/collect_run_bundle.py` |
| 依赖 | 仅 Python 标准库（`hashlib` / `json` / `pathlib` …），无第三方依赖 |
| 是否调用 SUT | **否**。源码中不存在 `subprocess` / `os.system` / 网络调用（有自检断言） |
| 是否属于评测器冻结清单 | **否**。不在 `run_eval.FROZEN_RELATIVE` 内，改动它不影响评测器指纹 |
| 产出物 | 一份 `<case-id>.json` 运行包，供 `run_eval.py --runs` 消费 |
| 自检 | `python evaluation/collect_run_bundle.py`（无参数即运行自检） |

## 3. 对外接口

### 3.1 Python API（主接口）

```python
from collect_run_bundle import collect_run_bundle, StaticBundleBackend

bundle = collect_run_bundle(
    case_dir,          # 用例目录（含 case.json），目录名即 case_id
    original_code,     # 原始代码目录 / 文件
    modified_code,     # 修改后代码目录 / 文件
    patch=None,        # 可选：改动补丁文件（仅登记溯源，不应用）
    backend=None,      # 采集后端；省略时用 NullBackend（不采集，仅提示未接入）
    workdir=None,      # 可选：执行侧工作目录（仅登记）
    line_tolerance=5,  # 代码定位行号容差
    extras=None,       # 可选：附加元数据，写入 collection.extras
) -> dict             # 运行包 dict
```

### 3.2 命令行

```powershell
# 组装：从静态测量文件产出运行包
python evaluation/collect_run_bundle.py `
  --case-dir case-01-slow-query-fullscan `
  --original case-01-slow-query-fullscan/project `
  --modified <修改后代码目录> `
  --backend static --from <已采集的原始测量.json> `
  --out runs/case-01-slow-query-fullscan.json

# 分文件读取各层
python evaluation/collect_run_bundle.py --case-dir ... --original ... --modified ... `
  --backend directory --raw-dir raw/ --out runs/<case-id>.json

# 仅校验一份已有运行包（不组装）
python evaluation/collect_run_bundle.py --check runs/case-01-slow-query-fullscan.json --case-dir case-01-slow-query-fullscan
```

参数：`--case-dir` / `--original` / `--modified` / `--patch` / `--workdir` / `--line-tolerance` /
`--backend {static,directory,null}` / `--from` / `--raw-dir` / `--out` / `--check` / `--json`。
退出码：`0` 通过；`1` 校验未通过；`2` 用法或 IO 错误。

## 4. 采集后端接口（**执行侧要实现的**）

模块把「谁来采数据」抽象成可插拔后端。基类为 `CollectorBackend`，**默认逐层抛
`CollectionNotImplemented`**——这正是「本模块不跑实验」的可执行断言。

执行侧只需继承基类、覆盖关心的层（在**属于执行侧**的代码里）：

| 方法 | 返回 | 对应评分参数 |
| --- | --- | --- |
| `collect_baseline(request)` | `dict` \| `None` | 基线重复测量 + 环境指纹 |
| `collect_report(request)` | `dict` \| `None` | **必需**：Agent 诊断结论 |
| `collect_trajectory(request)` | `dict` \| `None` | 过程轨迹 |
| `collect_retest(request)` | `dict` \| `None` | 独立复测结果 |
| `collect_artifacts(request)` | `list` \| `None` | 制品引用与完整性 |
| `collect_restore(request)` | `dict` \| `None` | 环境回滚 |
| `collect_cost(request)` | `dict` \| `None` | 成本层 |

内置后端（无需执行侧介入，供离线组装 / 测试）：

| 后端 | `name` | 行为 |
| --- | --- | --- |
| `StaticBundleBackend(payload)` | `static-bundle` | 从一份「已采集好的原始测量 JSON」读取各层 |
| `DirectoryBackend(raw_dir)` | `directory` | 从目录下 `<layer>.json` 分文件读取各层 |
| `NullBackend()` | `null-execution` | 逐层抛 `CollectionNotImplemented`（显式「未接入」） |

## 5. 评分参数全清单（运行包字段）

> 这是「获取评分所用的全部参数」的**权威清单**，与评测器读取键一一对应。
> 表可直接给执行侧当**采集清单**使用。字段缺失不会被评测器拒绝，但会按默认值（多为未达标）计分。

### 5.1 `baseline`（基线，用于可复现性判定）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `repeats_ms` | `number[]` | 原始代码基线的重复测量（毫秒）。建议 ≥3 次（`BASELINE_MIN_SAMPLES`） |
| `environment_fingerprint` | `object` | 环境指纹（OS/JDK/MySQL…），自由结构，仅登记 |

> 判定口径：**验收 ≤ 25%**（入库要求）、**运行·复测 ≤ 10%**（本次测量可复现）。

### 5.2 `report`（**必需**，Agent 诊断结论）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task.status` | `string` | 任务状态；`blocked`/`partial` 会被视为「证据不足」 |
| `findings[]` | `array` | 诊断发现列表，见下 |
| `observations[]` | `array` | 观测列表；元素为 `bool` 或 `{business_valid\|valid: bool}` |
| `insufficient_evidence` | `bool` | 是否声明「证据不足」（失败用例 honesty 判定用） |
| `reason` | `string` | 结论理由（失败/证据不足时必填才有分） |

`findings[]` 单条：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `string` | `verified` / `lead` / `refuted` / `unclassified`（硬闸门看 `verified`） |
| `code_locations[]` | `array` | `{path, line, commit?, association_evidence_ids?}`；定位命中容差默认 ±5 行 |
| `evidence_refs[]` | `string[]` | 证据引用（如 `artifact://...`），需与 `artifacts` 对得上 |
| `excluded_explanations[]` | `array` | 被排除的干扰解释；元素为 `string` 或 `{explanation, evidence_ids?}` |
| `limitations[]` | `string[]` | 声明的限制项（边界/失败用例的 `limitation_declared` 判定用） |
| `recommendation` | `object` | `{validation_status, measured_gain_percent}`；`validation_status=retested` 表示已复测 |
| `evidence_flags` | `object` | 6 项布尔证据，见下（`verified` finding 需**全为真**才证据合规） |

`evidence_flags` 六个键（`contract.EVIDENCE_FLAGS`）：
`scan_rows_decreased`、`duration_distinguishable`、`business_result_consistent`、
`no_lock_wait`、`cache_known`、`linked_to_code`。

### 5.3 `trajectory`（过程证据）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `required_steps_done[]` | `string[]` | 已完成步骤；必需步骤：`baseline`/`hypotheses`/`discriminating_experiment`/`localization`/`verification` |
| `hypothesis_count` | `int` | 假设数；约束 ≤ 3 |
| `experiments_single_variable` | `bool` | 实验是否单变量 |
| `records_retained` | `bool` | 是否保留记录（失败用例 honesty 判定用） |
| `tool_calls` | `int` | 工具调用次数 |

### 5.4 `retest`（独立复测）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `performed` | `bool` | 是否执行复测 |
| `improvement_percent` | `number` | 目标指标改善幅度 |
| `business_assertions_passed` | `bool` | 复测后业务断言是否全部通过 |

### 5.5 `artifacts[]`（制品证据）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ref` | `string` | 制品引用 |
| `sha256_verified` | `bool` | 校验和是否通过 |
| `readable` | `bool` | 是否可读取 |

> `artifact_integrity` 要求所有制品 `sha256_verified && readable` 均为真。

### 5.6 `restore`（环境回滚）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rolled_back` | `bool` | 是否已回滚 |
| `verified` | `bool` | 回滚后校验是否通过 |

### 5.7 `cost`（成本层）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `wall_seconds` | `number` | 墙钟耗时（预算：正常/失败 120s，边界 180s） |
| `tool_calls` | `number` | 工具调用总次数（预算：正常/失败 40，边界 60） |
| `artifact_bytes` | `number` | 制品总字节（预算：正常/失败 6e6，边界 1e7） |

> 超预算不置零，由 `cost_score()` 按比例衰减；是否硬判由用例 `evaluation.cost_gate` 决定。

### 5.8 可选顶层键（不属任何层）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `honesty_override` | `string` | 人工覆盖 `honesty`：`pass` / `partial` / `fail` |
| `line_tolerance` | `number` | 代码定位行号容差，缺省 5 |
| `runs` | `array` | **单用例多次运行**：每个元素与单包同形（`report`/`trajectory`/`retest`/`artifacts`/`restore`/`cost`）；顶层 `baseline` 按用例共享。**缺省即视为 1 次运行**。评测器聚合规则（数值取均值、布尔取多数、`false_verified` 取「或」、闸门取「与」）见《Agent 评估方法》与《执行侧数据导出对接规范》 |

## 6. 组装产物：运行包结构

```jsonc
{
  "baseline":   { "repeats_ms": [...], "environment_fingerprint": {...} },
  "report":     { "task": {"status": "completed"}, "findings": [ ... ] },   // 必需
  "trajectory": { "required_steps_done": [...], "hypothesis_count": 2, ... },
  "retest":     { "performed": true, "improvement_percent": 83.1, ... },
  "artifacts":  [ {"ref": "...", "sha256_verified": true, "readable": true} ],
  "restore":    { "rolled_back": true, "verified": true },
  "cost":       { "wall_seconds": 41.5, "tool_calls": 16, "artifact_bytes": 2048 },

  // 由本模块自动附加，评测器会忽略（不参与判分），仅供溯源
  "collection": {
    "module": "collect_run_bundle", "module_version": "0.1.0",
    "generated_at": "2026-10-05T14:52:14+00:00",
    "backend": "static-bundle",
    "case_id": "case-01-slow-query-fullscan",
    "case_dir": "case-01-slow-query-fullscan",
    "original_code": { "path": "...", "kind": "dir", "exists": true,
                       "sha256": "07ee3974...", "files": 12, "bytes": 11181 },
    "modified_code": { "path": "...", "sha256": "..." },
    "patch": null, "workdir": null, "line_tolerance": 5,
    "layers_present": [ ... ], "layers_unimplemented": [], "extras": {}
  }
}
```

`collection` 块把运行包**绑定到确定的代码版本**（原始/修改代码的 sha256 + 文件数），
使「这个分数对应哪一版代码」可复现、可追溯。

## 7. 校验规则（`validate_bundle`）

| 类别 | 规则 | 级别 |
| --- | --- | --- |
| 必需层 | 缺 `report` | **error** |
| 层类型 | `baseline/report/trajectory/retest/restore/cost` 须为对象；`artifacts` 须为数组 | **error** |
| report 细项 | `report.findings` 若存在须为数组 | **error** |
| baseline 细项 | `repeats_ms` 若存在须为数值数组；缺失则无法做可复现性判定 | error / warn |
| artifacts 细项 | 每个元素须为对象 | **error** |
| 用例对应 | `--case-dir` 下无 `case.json`；`collection.case_id` 与目录名不符 | error / warn |
| 建议层 | 缺 `baseline/trajectory/retest/artifacts/restore/cost` | warn |

> `ok = 无 error`。**警告应尽量消除**——它意味着对应指标会按默认值（多为未达标）计分。

## 8. 协作边界

```
【执行 / 采集侧（组员 A）】                          【评测 / 判分侧（本方）】
原始代码 + 修改后代码
      │
      │  ① 实现 CollectorBackend（跑实验、采数据）
      ▼
   运行包 runs/<case-id>.json  ──── 交接物 ────▶  ② run_eval.py --runs runs --out out
                                                      │
                                                      ▼
                                                 report.json / report.md
```

| 事项 | 执行侧 | 评测侧 | 本模块 |
| --- | :---: | :---: | :---: |
| 启动 SUT / 跑压测 / 采轨迹制品 | ✅ | ❌ | ❌ |
| 实现 `CollectorBackend` | ✅ | | 提供接口 |
| 组装运行包 / 溯源指纹 / 校验 | | | ✅ |
| 指标计算 / 闸门 / 报告 | | ✅ | |

**边界一句话**：本模块止步于「运行包」；它既不会替执行侧跑实验，也不会替评测侧打分。

## 10. 执行侧接入最小示例

```python
# 本文件应放在【执行侧】代码中，不属于 datasets/ 工程
import sys
sys.path.insert(0, "datasets/evaluation")          # 或按你的工程结构调整

from collect_run_bundle import CollectorBackend, collect_run_bundle
from collect_run_bundle import validate_bundle
import json

class ComposeExecutionBackend(CollectorBackend):
    """执行侧实现：这里才是真正跑实验的地方。"""
    name = "compose-exec"

    def collect_baseline(self, request):
        repeats = my_runner.run_baseline(request.original_code)   # 执行侧自有框架
        return {"repeats_ms": repeats, "environment_fingerprint": my_runner.fingerprint()}

    def collect_report(self, request):
        return my_agent.read_report()                            # 被测 Agent 的诊断结论

    def collect_trajectory(self, request):
        return my_agent.trajectory()

    # …按需覆盖其余层；未覆盖的层会视为「未提供」

bundle = collect_run_bundle(
    "case-01-slow-query-fullscan", "orig/", "fixed/",
    backend=ComposeExecutionBackend(), patch="change.patch")

result = validate_bundle(bundle)
assert result.ok, result.errors
json.dump(bundle, open("runs/case-01-slow-query-fullscan.json", "w", encoding="utf-8"),
          ensure_ascii=False, indent=2)
```

## 11. 常见问题

| 问题 | 回答 |
| --- | --- |
| 模块会替我跑实验吗？ | ❌ 不会。跑实验须由执行侧实现 `CollectorBackend`。 |
| 没有 `report` 能出分吗？ | ❌ 不能，`report` 是唯一必需层；缺它校验直接 error。 |
| `collection` 块会影响分数吗？ | ❌ 不影响，评测器只读 `LAYERS` 中的键；它纯粹用于溯源。 |
| 能不能不改代码，直接拿现成测量出包？ | ✅ 可以，用 `StaticBundleBackend` / `DirectoryBackend`。 |
| 运行包放哪里？评测器怎么找？ | 放 `--runs` 目录下，文件名必须是 `<case-id>.json`。 |
| 改了本模块会不会导致评测器指纹变化？ | ❌ 不会，它不在 `FROZEN_RELATIVE` 内。 |
| 中文输出会不会在 CI 上乱码？ | 建议设 `PYTHONIOENCODING=utf-8` 运行；模块输出不含未转义非 ASCII 的结构体（JSON 用 `ensure_ascii=False`）。 |

---

> **边界重申**：`datasets/` 只造「考题」与「判卷规则」；「进考场答题（跑实验）」由执行侧负责。
> 双方唯一交接物是**运行包 JSON**，其字段清单以本文第 5 节为准。
