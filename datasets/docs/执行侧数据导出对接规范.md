# 执行侧数据导出对接规范

> 面向读者：负责**执行 / 采集**的组员（跑实验、跑被测 Agent、导出运行记录的人）与队长
> 关联文档：`docs/评测器能力边界说明.md`（先读）、`docs/运行包采集模块交接说明.md`、`docs/Agent评估方法.md`
> 交付物：`scripts/export_evaluation_run.py`（只读导出器） + 本规范（双方对接契约）

---

## 1. 一句话

`scripts/export_evaluation_run.py` 是**执行侧**的**只读**导出器：把被测 Agent（project-doctor）
在 AGH 里**真实跑过**的一次任务记录，导出成评测器可直接消费的**运行包（run bundle）**。

> **它只读。** 不读 `case.json`、不启动被测 Agent（SUT）、不改动任何工作区，
> 也不改写父任务报告；每条制品都做 SHA-256 校验，把「这个分数对应哪一次真实运行」钉死。

评测侧（本方，`datasets/`）**只消费**这份运行包并打分，绝不参与执行。双方唯一的交接物
就是运行包 JSON——本规范定义它的**生成方式、字段含义与多次运行契约**。

---

## 2. 位置与定位

| 项 | 内容 |
| --- | --- |
| 脚本路径 | `scripts/export_evaluation_run.py` |
| 运行环境 | 需在 `project-doctor` 工程内运行（复用其 `TaskBundle` / `ReportResult` / `Finding` 等内部模型） |
| 是否读 `case.json` | **否**（评测方的答案不在执行侧可见范围内） |
| 是否启动 SUT | **否**（源码中不存在启动进程 / 调 SUT 的路径） |
| 是否写入被测工程 | **否**（只写 `--out` 指定的运行包文件） |
| 产出物 | 一份 `<case-id>.json` 运行包，供评测器 `run_eval.py --runs` 消费 |
| 入口 | `main()`（命令行，见第 4 节） |

## 3. 数据来源（输入：一次 AGH 运行目录 `--home`）

`--home` 指向被测 Agent **一次任务运行**的落盘目录，导出器从中读取：

| 文件 / 目录 | 用途 | 必需 |
| --- | --- | --- |
| `bundle.json` | `TaskBundle`：任务/项目/环境、实验与观测、findings、证据引用、资源用量 | **必需** |
| `finish_task-latest.json` | `ReportResult`：最终报告（`task_id` / `task_status` / `limitations` / `json_ref` / `html_ref`） | **必需** |
| `artifacts/` | 制品根目录（读取受 `resolve_contained` 约束，只允许访问根内路径） | 建议 |
| `business-tool-calls.jsonl` | 逐行工具调用记录（`name` / `args` / `kwargs` / `result` / `error` / `started_at` / `ended_at`） | 建议 |
| `session.jsonl` | 会话事件（可选；存在时来源标记为 `actual_task_and_agh_records`） | 可选 |
| `summary.json` | 会话汇总（`model_elapsed_seconds` / `elapsed_seconds` / `execution_mode` / `task`） | 可选 |

导出器会做一致性校验，不一致直接报错（`ValueError`），避免导出张冠李戴的运行包：

- `finish_task-latest.json` 的 `task_id` 必须等于 `bundle.json` 的任务 id；
- 报告 `task_status` 必须与任务最终状态一致；
- 保存的报告（`json_ref`）必须存在、可读且通过 SHA-256 校验；
- 报告中 `cards[].finding` 必须与 `bundle.findings` 完全一致；
- `summary.json` 若给出端到端墙钟时间，必须是有限非负数。

## 4. 命令行接口

```powershell
# 导出单次运行
python scripts/export_evaluation_run.py `
  --home <AGH运行目录> `
  --case-id case-01-slow-query-fullscan `
  --out runs/case-01-slow-query-fullscan.json

# 附带独立复测（另一次同项目/同 commit、不同任务的运行）
python scripts/export_evaluation_run.py `
  --home <原任务运行目录> `
  --case-id case-01-slow-query-fullscan `
  --retest-home <独立复测运行目录> `
  --out runs/case-01-slow-query-fullscan.json
```

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `--home` | ✅ | 被测 Agent 一次运行的落盘目录 |
| `--case-id` | ✅ | 对应数据集用例 id（写入包内 `collection.case_id`） |
| `--out` | ✅ | 运行包输出路径；文件名必须为 `<case-id>.json` |
| `--retest-home` |  | 独立复测运行目录；给出时调用 `attach_retest()` 附加复测结果（见第 6 节） |

退出码：正常 `0`；输入不一致 / 校验失败由异常抛出，非零退出。

## 5. 导出产物：单次运行包结构

```jsonc
{
  "baseline":   { "repeats_ms": [12.1, 11.8, 12.4], "environment_fingerprint": { ... } },
  "report":     { "task_status": "completed", "findings": [ ... ], "observations": [ true ],
                  "insufficient_evidence": false, "reason": "..." },
  "trajectory": { "steps": [ ... ], "required_steps_done": [ ... ], "hypothesis_count": 2,
                  "experiments_single_variable": true, "records_retained": true, "tool_calls": 16 },
  "retest":     { "performed": false, "improvement_percent": null,
                  "business_assertions_passed": false },
  "restore":    { "rolled_back": true, "verified": true },
  "artifacts":  [ { "ref": "artifact://...", "sha256_verified": true, "readable": true } ],
  "cost":       { "wall_seconds": 41.5, "tool_calls": 16, "artifact_bytes": 2048 },
  "collection": { "case_id": "...", "task_id": "...", "target_commit": "...", ... }
}
```

各键与评测器读取字段的对应关系（评测器字段定义见 `evaluation/contract.py`）：

| 顶层键 | 评测器字段 | 说明 |
| --- | --- | --- |
| `baseline` | `baseline.repeats_ms` / `environment_fingerprint` | 原始代码基线的重复测量（毫秒）；用于**可复现性**判定 |
| `report` | `report.*` | **唯一必需层**；缺失即无法出分 |
| `trajectory` | `trajectory.*` | 过程证据（必需步骤、假设数、单变量、记录保留、工具调用数） |
| `retest` | `retest.*` | 独立复测；未做时 `performed=false`（对应指标按未达标计） |
| `restore` | `restore.rolled_back` / `verified` | 环境回滚 |
| `artifacts` | `artifacts[]` | 制品完整性：要求每条 `sha256_verified && readable` |
| `cost` | `cost.wall_seconds` / `tool_calls` / `artifact_bytes` | 成本层（超预算按比例衰减，不置零） |
| `collection` | ——（**忽略**） | 仅溯源，不参与判分，但必须保留以保证可复现 |

### 5.1 `report`（必需层）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_status` | `string` | `created` / `running` / `blocked` / `completed` / `partial`；`blocked`/`partial` 视为「证据不足」 |
| `findings[]` | `array` | 诊断发现列表，见下 |
| `observations[]` | `bool[]` | 各观测的业务有效性（导出器已把 `Observation.business_valid` 摊平为布尔） |
| `insufficient_evidence` | `bool` | 是否声明证据不足 |
| `reason` | `string` | 结论理由（去重后以 `; ` 连接） |

`findings[]` 单条：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `string` | `verified` / `lead` / `refuted` / `unclassified`（硬闸门看 `verified`） |
| `code_locations[]` | `array` | `{path, line, commit?, association_evidence_ids?}`；定位命中容差默认 ±5 行 |
| `evidence_refs[]` | `string[]` | 证据引用（`artifact://<id>`），需与 `artifacts` 对得上 |
| `excluded_explanations[]` | `array` | 被排除的干扰解释 |
| `limitations[]` | `string[]` | 声明的限制项 |
| `recommendation` | `object` | `{validation_status, measured_gain_percent}`；`retested` 表示已复测 |
| `evidence_flags` | `object` | 6 项布尔证据（见第 5.2 节）；`verified` finding 需**全为真**才证据合规 |

### 5.2 `evidence_flags`（6 项证据位）

由导出器 `evidence_flags(bundle, finding)` 从实验/观测/SQL 调用**确定性**汇总，键与
`contract.EVIDENCE_FLAGS` 一致：

| 键 | 含义 |
| --- | --- |
| `scan_rows_decreased` | 索引干预前后扫描行数下降（`rows_examined` 中位数下降） |
| `duration_distinguishable` | 耗时可区分（`MeasurementPolicy` 下两水平可分辨） |
| `business_result_consistent` | 业务结果一致（各观测 `business_valid` 且结果摘要唯一） |
| `no_lock_wait` | 无锁等待（见下方语义说明） |
| `cache_known` | 缓存状态已知（两次准备结果均已验证） |
| `linked_to_code` | 能关联到代码位置（每条 SQL 调用都有 `code_location`） |

> **`no_lock_wait` 语义（写入 `collection.evidence_flag_semantics`）**：表示锁覆盖完整，
> 且**实测的表锁 + InnoDB 行锁等待与 MDL 上界不足以解释 SQL 收益**——它是「锁不是收益来源」
> 的**上界**断言，**不是**「锁等待恰好为零」的声明。
>
> 若 finding 的 `evidence_refs` 为空或与 `artifacts` 不对应，则 6 个证据位**全部置 false**。

### 5.3 `collection`（溯源块，评测器忽略）

| 字段 | 说明 |
| --- | --- |
| `case_id` / `task_id` / `target_commit` | 用例、任务、目标 commit |
| `source` | `actual_task_and_agh_records`（有 `session.jsonl`）或 `actual_task_and_platform_records` |
| `session_events` | 会话事件条数 |
| `execution_mode` | 执行模式（缺省 `agh_model_run`） |
| `wall_time_scope` | 墙钟口径：`task_usage_or_observed_tool_span` / `recorded_end_to_end` / `observed_tool_span_including_prior_attempts` |
| `platform_usage_wall_seconds` | 平台记录的墙钟秒数 |
| `missing_measurements` | 未采集项清单（缺省 `independent_retest` / `api_cost` / `model_tokens`） |
| `policy` | 评测侧 `MeasurementPolicy` 参数快照 |
| `evidence_flag_semantics` | 证据位语义注解 |

## 6. 独立复测附加（`--retest-home` → `attach_retest()`）

独立复测必须是**另一次**运行，用于验证 Agent 的建议在被评测方独立重放后仍成立。附加前
导出器做 5 类校验，任一不满足即报错：

1. 复测任务须**新任务 id、新环境 id、同项目/同 commit**；
2. 原任务与复测任务各**有且仅有 1 个实验**，且实验协议（除 `task_id`/`snapshot_id`/
   `baseline_fingerprint` 外）**完全一致**；
3. `retest-link.json` 的 `source_task_id` / `source_experiment_id` / `retest_task_id` /
   `source_commit` / `recipe_ref` 与真实任务/规格一致；
4. 两次运行的隔离工作区（`settings.json.workspace_root`）**不得互相包含**；manifest/
   recipe（除新快照 id 外）不得变化；
5. 复测**不得复用**原运行的 `request_id`。

通过后，导出器**只改写 payload 的 `retest` 与 `collection`，绝不重写父报告**，并追加：

| 新增字段 | 说明 |
| --- | --- |
| `retest.performed` | 复测是否有效（任务完成、实验 finished、无失败、回滚校验通过、制品全部有效） |
| `retest.improvement_percent` | 改善幅度（基于复测两水平延迟中位数，可测时给出） |
| `retest.business_assertions_passed` | 复测后业务断言是否全部通过 |
| `retest.repeats_ms` / `findings` / `cost` / `trajectory` | 复测自身的原始测量与产物 |
| `retest.same_data_snapshot_digest` / `cross_run_business_digest_match` | 与原运行的数据快照/业务结果一致性 |
| `collection.diagnosis_cost` / `cost_scope` | 复测前后的成本口径 |

同时：`cost` 的 `wall_seconds` / `tool_calls` / `artifact_bytes` 与原运行**相加**（口径
`diagnosis_plus_independent_retest`）；`artifacts` 去重合并；有效复测后从
`missing_measurements` 移除 `independent_retest`。

## 7. 只读与脱敏保证

| 保证 | 实现 |
| --- | --- |
| 路径越界防护 | 制品读取一律经 `resolve_contained(root, relative_path)`，禁止逃逸 `artifacts/` 根 |
| 完整性校验 | 逐制品比对 `size_bytes` 与 `sha256`，并尝试读取；不合规记为 `sha256_verified=false` |
| 敏感信息脱敏 | `redact()` 递归处理，键名含 `password` / `api_key` / `authorization` / `secret` 的值一律替换为 `[REDACTED]` |
| 不接触答案 | 从不读取 `case.json` / `docs/` / `_schema/` |
| 不执行被测系统 | 无 `subprocess` / `os.system` / 网络调用路径 |

## 8. 多次运行取平均契约（**本版新增**）

单用例可**重复执行多次**以抑制采样噪声。评测侧的口径是：**用例得分为 N 次运行的聚合结果**
（数值取平均），运行包格式随之扩展如下。

### 8.1 运行包格式

```jsonc
{
  "baseline": { "repeats_ms": [ ... ], "environment_fingerprint": { ... } },  // 顶层：按用例共享
  "runs": [
    { "report": {...}, "trajectory": {...}, "retest": {...},
      "artifacts": [ ... ], "restore": {...}, "cost": {...} },               // 第 1 次运行
    { "report": {...}, "trajectory": {...}, "retest": {...},
      "artifacts": [ ... ], "restore": {...}, "cost": {...} }                // 第 2 次运行
  ]
}
```

- `baseline`（环境基线）**只放顶层**，按用例共享，**不随 `runs` 重复**；评测器只读顶层 `baseline`。
- `runs` 的每个元素与「单次运行包」**同形**（`report`/`trajectory`/`retest`/`artifacts`/`restore`/`cost`）。
- **缺省 `runs` 时，整包视为 1 次运行**——既有单次运行包**行为逐位不变**（金标准回归依赖此约定）。

### 8.2 如何从多次导出组装（执行侧）

导出器每次只导一次运行；重复执行 N 次，把各自的运行包**去掉 `baseline` 后**装进 `runs`
即可（示意，非交付代码）：

```python
from export_evaluation_run import export_run   # scripts/export_evaluation_run.py

homes = [home_1, home_2, home_3]               # 同一用例的 N 次独立运行目录
payloads = [export_run(h, case_id) for h in homes]

bundle = {
    "baseline": payloads[0]["baseline"],       # 顶层共享（建议取首个，或合并各次 repeats_ms）
    "runs": [{k: v for k, v in p.items() if k != "baseline"} for p in payloads],
}
```

> 文件名仍为 `<case-id>.json`；多次运行只是**改变包内结构**，评测器调用方式（`--runs <目录>`）不变。

### 8.3 聚合规则（评测侧 `merge_case_results()`）

| 指标类别 | 聚合方式 |
| --- | --- |
| 数值指标（`root_cause_recall`、`trajectory_conformance`、墙钟…） | **算术平均** |
| 布尔指标（一般） | **多数**（出现次数 > 半数） |
| 布尔指标 `false_verified` | **或**：任一次误验证即判误验证（**零容忍**，不因平均被稀释） |
| 分类指标 `decision_match` | **众数**，并列时取更严重一档（`over` > `under` > `exact`） |
| 分类指标 `honesty` | **众数**，并列时取更严重一档（`fail` > `partial` > `pass`） |
| 硬闸门 / 用例通过 | **与**：任一次不通过即不通过 |
| 奖励 `total` | 用**聚合后的指标**经 `total_score()` 重算 |
| 成本 `cost_score` | 各次均值；`exceeded` 超预算项取**并集**，逐项数值取均值 |
| 白盒步骤层（D4，仅供归因） | 取**首次运行**轨迹作代表，不跨次拼接（避免虚高） |

### 8.4 评测侧产出（便于核对）

- 逐用例：`cases[].repeats`（运行次数）、`cases[].repeat_totals`（各次总分）；
- 全局：`global.repeats_total`（合计运行次数）、`global.mean_repeats_per_case`（平均每用例次数）；
- `report.md` 新增一行「用例重复执行：合计 N 次运行，平均每用例 X 次（多次运行的指标取平均）」。

## 9. 验收与对接清单

导出并交接前，逐项确认：

- [ ] `--out` 文件名为 `<case-id>.json`，且 `collection.case_id` 与之一致；
- [ ] `report` 存在且非空（唯一必需层）；
- [ ] `baseline.repeats_ms` 建议 ≥ 3 次（`BASELINE_MIN_SAMPLES`），离散度满足验收口径 ≤ 25%；
- [ ] `artifacts` 中需被引用的制品全部 `sha256_verified && readable`；
- [ ] `restore.rolled_back && restore.verified`（回滚到位）；
- [ ] 需要独立复测时提供 `--retest-home`，且满足第 6 节 5 类校验；
- [ ] 多次运行时，`baseline` 只在顶层、`runs` 元素与单次运行包同形，**不要**把 `baseline` 塞进每个 `run`。

## 10. 常见问题

| 问题 | 回答 |
| --- | --- |
| 导出器会跑实验吗？ | ❌ 不会。它是**只读**导出器，跑实验由执行侧的运行框架完成。 |
| 导出器会读 `case.json` 吗？ | ❌ 从不。评测方的答案对执行侧不可见。 |
| 只有一次运行能出分吗？ | ✅ 能。缺省 `runs` 时整包视为 1 次运行，行为与旧版完全一致。 |
| 多次运行怎样抑制噪声？ | 数值取平均、布尔取多数、闸门取「与」；但 `false_verified` 仍**零容忍**。 |
| 复测结果由谁产生？ | 由评测方**另行**独立重放；导出器只做**校验与附挂**（`--retest-home`），不改父报告。 |
| 敏感字段会不会外泄？ | 不会。含 `password` / `api_key` / `authorization` / `secret` 的键值一律 `[REDACTED]`。 |
| 中文会不会乱码？ | 运行包以 `ensure_ascii=False, indent=2` 写出；建议 `PYTHONIOENCODING=utf-8` 运行。 |

---

> **边界重申**：执行侧负责「进考场答题并如实导出记录」；本方（`datasets/`）负责「考题 +
> 判卷规则」。双方只通过**运行包 JSON** 交接，多次运行的契约以本文第 8 节为准。
